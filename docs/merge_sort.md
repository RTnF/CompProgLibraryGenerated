# 整数マージソート

## 実装と仕様

`library/merge_sort.hpp` は `std::vector<int> cp::merge_sort(std::vector<int>)` を提供する。入力値を二分し、各半分を再帰的に整列してから、自分で書いたループで併合する。C++ 標準ライブラリのソート・併合関数は使わず、実行は単一スレッドで行う。

入力長 `n ≤ 300000` と必要なメモリ確保の成功を前提に、戻り値は入力と同じ多重集合で非減少順となる。入力長が 0 または 1 ならそのまま返す。`int` の値について加減算はせず、比較のみ行う。

## 証明の範囲

`verifier/merge_sort_bridge.py` は Lean 4.34.1 に同梱された Clang 22.1.4 と GCC 13.3.0 のヘッダで `cp::merge_sort` の構文木を取得し、レビュー済みの正規化 SHA-256 に一致することを確認する。その構文木の二分・再帰・併合を `Proofs/Generated/MergeSort.lean` のリスト演算に対応付ける。この対応付けはソース固有の**信頼前提**であり、汎用 C++ 意味論や変換器の正しさを Lean で証明したものではない。ソース変更時は構文木と意味対応を再レビューする。

生成された Lean モデルも二分と併合を再帰的に定義し、既製のソート関数は呼ばない。`Proofs/MergeSort.lean` はそのモデルについて次を証明する。

- `model_perm`: 戻り値が入力の順列である。
- `model_sorted`: 戻り値が非減少順である。
- `split_bounds`, `merge_left_step`, `merge_right_step`: 二分位置、添字の増加、ループ残量の境界を示す。
- `total_work_bound`: 長さ `n ≥ 1` に対し、線形の分割・併合仕事量と再帰呼び出し数の和が `n * (Nat.log2 (n - 1) + 3)` 以下。従って採用した費用モデルで時間は `O(n log n)`。
- `slots_linear`: 同時に保持する整数要素数のモデルが `4n` 以下。追加領域は `O(n)`。

`std::vector<int>` の範囲構築、`size`、添字参照、`reserve`、`push_back`、返却と破棄について、[C++ 標準ライブラリ仕様](https://eel.is/c++draft/vector)どおりの結果と計算量を信頼する。領域の `4n` 上界は**保持する整数要素数のモデル**であり、実際の確保容量や管理情報まで 4n 個に抑える主張ではない。実メモリを `O(n)` とみなすには、GCC 13.3.0 の `std::vector` が長さに比例した容量を確保するという追加前提を置く。割り当て成功、Clang による解析、変換器の対応付け、コンパイラの仕様準拠も信頼前提とする。Lean の主要定理の公理一覧は `propext` と `Quot.sound` で、補助定理の一部は `Classical.choice` も使う。CI はこれらの標準公理だけを許可し、`sorryAx` は許可しない。

## テストと実測

`tests/merge_sort.cpp` は長さ 0〜8 の三値入力を網羅し、整数の最小値・最大値を含む例と 30 万要素の固定シード乱数入力も確認する。順序と出現回数を別々に検査する。`tools/public.py` が `a.cpp` に部品を貼った結果も C++17 でコンパイルする。

`benchmarks/merge_sort.cpp` は `n = 300000` の一様な `int` 値を、異なる五つの固定シードで生成する。乱数生成と整列結果のチェックは時間計測から除き、`cp::merge_sort` の呼び出しを測る。入力ハッシュ、コンパイラ、VM と全結果は[測定記録](../benchmarks/merge_sort_2026-09-29.md)を参照する。全実行は直列であり、並列ソートは行わない。
