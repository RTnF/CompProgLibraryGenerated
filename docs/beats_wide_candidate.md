# 元の入力範囲を保つBeats構築の候補

`experiments/verification/segment_tree_beats_wide.hpp` は公開版からの修正候補である。準備済みの1vector入力から、実15配列確保を含むstageの正常終了・木の表現・最終buffer内容・仕事量/peakまで一般証明し、root入力のprepareにも接続した。row入力の一般性、公開ヘッダーへの切替、class export/寿命とその資源、独立検証は未完了である。

元の構築が `4*n` と次の2冪の木を32-bit intで扱える範囲に対し、公開版の `8*n+8` は先にintの上限へ達する。候補は12本の確保長をunsigned 64-bitで計算し、構成子が全 `4*n` 位置を走査するときの子添字2個も64-bitにする。未使用節点に対しても子のlo/hiを更新するため、確保長だけの修正では足りない。

`Proofs/BeatsIndexHeight.lean` は、中点分割の木の高さとheap添字の関係を示す。`4*n < 2^31` なら高さは29以下、全ての実節点の子添字は `2147483647` 未満となる。操作側はこの範囲に収まるため、候補で6操作とそのヘルパーを書き換える必要はない。初期の広い変更案はcacheへ保存し、現候補は構成子だけを変更する。

同モジュールは構築の走査添字と確保長の上界、二つのIdxOKの最小値への合成、Capacitiesの下界縮小も扱う。`BRepS.cap_indices` は、実配列の長さLがint上限を超えても、表現の下界を `min L 2147483647` に縮めて既存操作の証明へ渡せることを示す。データ・意味・所有権・スタック容量は保つ。これは広い構築の正常終了を仮定する代わりではなく、構築の表現が得られた後に使う補題である。

`tests/test_beats_wide_candidate.py` は、3000例×60操作の既存ケースと大きい値のケースを候補に対して通常実行・ASan/UBSanで確認する。巨大配列を作らず、n=2^28と元のintサイズ計算の最大値付近の算術も検査する。実候補から確保を含むstageと本体モデルを生成してLean型検査し、確保長の型がunsigned 64-bitであること、本体のslot置換、構成子以外の全生成関数が公開版と完全一致することを要求する。

これらの検査は大きい配列を実確保した実測ではない。以下の補助証明で4*nのint境界と64-bitの子添字/確保長を分離し、末尾に示すBeatsInlineFrame/Execで実確保からインライン本体まで接続した。一般証明は、記載した入力範囲・値域・正しいcaller表現・標準vector契約を前提にする。class export/寿命、確保を含む全体資源、独立カーネルと全件検査は未完了である。

`Proofs/BeatsWideExec.lean` はunsigned 64-bitのliteral・cast・localの補助評価と変換を扱う。`den_wide_child` は実候補と同じ `2ULL*(unsigned long long)k+d` を評価し、kがint範囲、d≤2ならunsigned演算もwrapせず数学的な `2*k+d` を返すことを示す。`den_wide_child_original_range` は元の `4*n<2^31`、走査中の `k<4*n` から、この評価と `2*k+d<8*n+8` を得る。子添字そのものにint範囲を要求しない。

候補の生成検査は、構築ループの実ソースから取り出した子添字式2個が `wideChild 19 1/2` にそれぞれrfl一致することもLeanで確認する。`tests/lean/beats_wide_exec.lean` はn=536870911、k=2147483643で子添字4294967288を得る境界例とk=0を扱う。この式の補助評価は構築ループ全体の正常終了・表現保存・資源の証明ではなく、それらへの接続が残っている。

`vden_wide_count` は入力vectorの実長さから確保長の式を評価する。元の `4*n<2^31` の範囲だけを使い、式中のsize、unsigned cast、積、和、最後のunsigned castを扱って `8*n+8` を得る。12本の実生成初期化式を `wideCount 0` とrfl照合し、元の最大サイズn=536870911で確保長4294967296を得る回帰例も加えた。入力vectorは抽象的なfamilyのままとし、巨大なlistや配列を構築しない。この補助評価はvector確保自体の成功・費用や、15本の確保後の表現不変条件を証明したものではない。

`BeatsExec_WideCtLoopDefs/Ch0..12` と `BeatsExec_WideCtLoop` は構築の最初の走査1回分を扱う。49命令を最大4命令ずつ13補題に分け、64-bit子添字の局所変数・読取り・書込みを接続する。補助実行器pexecMでの結果状態・配列内容・正常終了と、仕事量20580以下、storage work12以下を示す。全補題は資源上限の変更を含まない。従来のint型の子添字を前提にした補題とは別に保持する。

`Proofs/BeatsWideCtorLoop.lean` の `ct_iter_wide` は構築不変条件CtInvから必要な値・型・添字の条件を導き、1回の走査後のCtInv、型の妥当性、node/stackを分離した容量条件、lo/hiの長さを保つ。`ct_loop_wide` は残りd回の走査を停止まで合成し、fuel≤d+1、仕事量≤d*20620+20、storage work≤d*12を得る。配列長Lには `8*n+8≤L` だけを要求し、従来の `L<2^31` を要求しない。int変数・loop条件の範囲は元の `4*n<2^31` から得る。生成検査では候補の実49命令と条件・scopeを含むwhile全体が、これらの定義とrfl一致することを要求する。

`Proofs/BeatsWideCtorExec.lean` は前後のループと本体の初期化命令を合成する。`inner_children_lt_four_n` は既存のrngOf_indexから、内部節点eの子添字が `4*n` 未満になることを示す。entered listの各要素が内部節点であることはCtInvとmem_LLrから得られるため、後半には容量下界 `min L 2147483647` を渡して既存の集約処理を再利用する。SameLenから元の物理配列の容量条件を回復する。実木全体のInSkへの新しい対応証明を、この集約処理のためだけに追加する必要はない。

`ct_exec_wide` は候補の構築本体WideCtorCmdについて正常終了、結果の配列と数学的な木の一致、ValidOK、容量・lo/hi・LenOK保存、仕事量≤4*n*45414+100、storage work≤4*n*18+10を示す。`ctor_rep_wide` は高さの上界と添字の条件を加えてBRepSを構成し、scalar need≤P.length+100も示す。これらは `4*n<2^31` を仮定し、L<2^31は仮定しない。Nbの一括decideは標準の再帰深度に達したため、構文の各場合をsimpで分解する証明に変更した。資源上限もneedの上界100も増やしていない。
