# xorshift

`cp::Xor64` は 64 bit の Xorshift 乱数生成器である。元の `experiments/library/cpp/random/xorshift.hpp` の `Xor64` から、状態更新 `get()` を取り出した。`get_int`、`get_ll`、`get_double`、`get_double(lo, hi)`、`get_normal` は、メソッドからメソッドを呼ぶ（`get()` を this に対して呼ぶ）か、浮動小数点を使うため、まだ変換器の対象外で `experiments/` に残している。コンストラクタ `Xor64(s)` は、引数をそのまま状態にする関数として変換され、`xor64_new_correct` が証明している。

- `get()`: 状態 `s` を `x = s; x ^= x << 7; x ^= x >> 9; s = x` に進め、新しい状態を返す。前提なし（`uint64_t` の全値）。結果は `[0, 2^64)`。状態 0 は 0 のまま（周期を得るには非零の種が必要）。
- 時間と領域: 分岐もループもない定数時間、定数個の局所変数。仕事量は 60 以下を証明している（呼び出し側の引数評価を除く）。

共通の変換器（`verifier/ast_stream.py` の `class_method_functions`）が、スカラーのフィールドだけを持つクラスのインラインメソッドを、通常の関数に直す。各フィールドは先頭の参照引数（const メソッドでは const 参照）になり、`this->field` はその引数の使用になる。スカラーのフィールドを 1 つだけ持つクラスは、`verifier/class_lowering.py` がそのフィールドの型の値に消去し、メソッドは第 1 引数を参照とする関数に、コンストラクタは値を返す関数になる。`Proofs/XorshiftCall.lean` の `xor64_get_correct` が、生成された `Xor64_get` について、呼び出しの結果（`xnext`）、フィールドの更新、停止、未定義動作の不在、仕事量と追加領域の上界を、前提を満たす全入力について証明する。直線的なスカラー断片の実行器（`Proofs/StraightLine.lean`）の上で、各文の結果を求めている。

定理に含めていないこと: 呼び出し側のオブジェクトの内容が変化しないこと（個数、使用領域、仕事量、スコープは保存を証明している）。C++ のテストは `tests/xorshift.cpp` で、独立に書いた状態更新と照合し、状態 0 の固定点と非零状態の持続も確かめる。
