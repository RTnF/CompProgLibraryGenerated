# 共通変換器の初期スカラー部分言語

`verifier/scalar_ir.py` は固定 Clang の AST を型付き IR に落とし、`Proofs/CppScalar.lean` の共通評価器を呼ぶ Lean 定義を生成する。関数名やソースのハッシュでアルゴリズムを選ぶ処理はない。名前は宣言の識別にだけ使い、引数と局所変数への参照は Clang の宣言 ID を位置番号へ変換する。ID は生成結果に残さない。

この基盤は全件検証計画の途中段階である。持ち込み部品の公開条件を満たすものではなく、既存2部品の専用 bridge からの移行もまだ行っていない。

分岐・更新・参照・具体化された関数テンプレートは、式の規則を共有する [状態の共通変換器](state_converter.md) で扱う。以下の対応範囲は、直線的なスカラー生成コマンドについての記録である。

## 対応範囲と拒否

対象は `cp::` に定義された、名前の重複しない、非可変長の通常関数。入力は値渡しの整数または bool。ゼロ個以上の自動局所変数の初期化に続いて、最後に1つの return がある本体を扱う。局所変数への再代入は未対応。`int` は32 bit、`long` と `long long` は64 bit とし、それぞれの符号なし型を含む。Clang の定義済みマクロでこの ABI を検査し、一致しなければ拒否する。bool の IR 幅1は値の表現範囲であり、C++ のオブジェクトサイズを表さない。

整数・bool のリテラル、局所宣言の参照、括弧、lvalue-to-rvalue、整数間と bool への暗黙変換、単項 `+ - !`、二項 `+ - * / % < <= > >= == !=` に対応する。Clang が挿入する整数昇格と通常の算術変換を IR の型と cast に保持する。

C形式 `(int)x`、`static_cast<int>(x)`、関数形式 `int(x)` の明示的な整数・bool の値変換も扱う。`CStyleCastExpr`、`CXXStaticCastExpr`、`CXXFunctionalCastExpr` の prvalue に限り、`IntegralCast` と `IntegralToBoolean` は共通の `Expr.cast` に落とす。Clang が実際の変換を子の暗黙変換ノードとして入れた場合、外側の `NoOp` は型の一致を確認して取り除く。これによって同じ変換を二度数えない。同じ型への無操作のキャストは読み出しの費用だけであり、実際の変換は1の仕事量を持つ。型別名を使う関数形式も正規化型に従う。

型別名は Clang が提供する正規化型に従う。関数型に正規化した返却型がない場合は、同じシグネチャの値引数で同じ型の綴りに提供された正規化型を使う。それ以外の未解決の返却型別名は拒否する。`ll` 等の綴りを整数型に固定して扱わない。

参照・ポインタ、配列、クラス、テンプレート、グローバル状態、static/volatile 局所変数、未初期化変数、関数呼び出し、代入、条件分岐、ループ、再帰、一般の短絡演算、条件演算子、リテラル左シフト以外のビット演算、未対応の宣言・属性は拒否する。明示的な参照・lvalue・xvalue へのキャスト、reinterpret_cast、const_cast、浮動小数点・ポインタ・クラスとのキャストは扱わない。副作用を含むキャストのオペランドも拒否する。副作用のある式を受け付けないため、二項式の左右の評価順序の違いは結果を変えない。将来これらを追加する際は評価順序・状態・メモリを拡張する必要がある。

AST 抽出は `cp::` の宣言を対象とする。ヘッダ全体の公開宣言照合やソース変更検出の登録ゲートへは未接続である。名前空間外のコード全体をこの段階で検証したとはしない。未対応の `cp::` 宣言が混ざれば生成を停止する。

## 意味と費用

IR は型の幅・符号・bool 区分、引数と局所変数の位置、演算、初期化順序、返却式を持つ。Lean では整数値を `Int` で持ち、引数と変数の読み出しで型の範囲を検査する。符号なし算術と変換は `2^幅` の剰余を取り、bool への変換は零か非零かで決める。符号付き算術の範囲超過は成功結果を返さない。C++17 の実装定義となる符号付き型への範囲外変換も、成功結果を返さず前提範囲から除外する。`none` が必ず C++ の未定義動作を意味するわけではない。

除算と剰余は共通の `Expr.divrem` と `checkedDivRem` に落とす。商には `Int.tdiv`、剰余には `Int.tmod` を使い、負数でも商を0方向へ丸める。除数が0なら拒否する。商が演算の型に表現できない場合は、剰余を求める場合も拒否する。このため符号付き最小値を −1 で割る `/` と `%` はともに拒否する。`checkedDivRem_success_safe` は成功時に除数が非零かつ商が型の範囲内であること、`checkedDivRem_zero` と `checkedDivRem_signed_min_neg_one` は危険な入力の拒否を証明する。後者は任意の幅を対象にする。これらは部品の入力条件全体を証明したものではない。

`Ty.convert_of_valid` は、既に型の範囲内の値の変換が値を保つことを証明する。これを使う `checkedDivRem_division_exact` と `checkedDivRem_remainder_exact` は、非零除数と商・結果の表現可能性の前提の下で商と剰余がそれぞれ `Int.tdiv`・`Int.tmod` と一致することを証明する。剰余の定理にも商の表現可能性を要求する。

成功時は値と抽象仕事量を返す。リテラル・読み出し・変換・演算は各1、局所変数の初期化の格納と return も各1と数える。環境リストは C++ の引数と局所変数の束縛のモデルであり、Lean のリスト走査・連結の実装費用を C++ の仕事量として数えるものではない。式については `Expr.eval_work` が、成功時の仕事量と式のノード数の一致を証明する。評価器の再帰は AST と局所変数リストに対する構造的な再帰である。

関数全体の結果・停止・未定義動作の不在・時間・追加領域の定理、および C++/AST/IR の意味対応の監査は未完了である。現在の評価器には追加領域のモデルはまだない。STL とメモリ操作も未対応である。

Clang、整数幅の ABI、AST → IR の規則、IR → Lean の生成器は信頼境界である。Lean の費用定理だけでこの意味対応を証明したとはしない。生成結果に手書きアルゴリズムを貼り付けたり、ハッシュ更新で意味対応を承認したりする経路は設けない。

## 再実行

```sh
python3 tests/test_scalar_ir.py
python3 tests/test_explicit_cast_ir.py
ELAN_HOME="$PWD/.tools/elan" python3 tools/offline.py .tools/elan/bin/lake env leanchecker Proofs.CppScalar
python3 verifier/scalar_ir.py SOURCE.cpp --ir /tmp/scalar.json --lean /tmp/scalar.lean
```

変換器とテストは seccomp の通信禁止下で動く。テストは専用スクリプトで C++ のケースを生成する。ローカル変数・関数名の変更で意味 IR が変わらないこと、定数・演算の変更で IR が変わることを検査する。C++ を実行した結果を生成 Lean モデルと比較し、初期12演算×49入力、符号なし32/64 bit の折り返し、符号付きオーバーフローと最小値の符号反転の拒否、bool 変換、引数の個数・範囲を確認する。除算・剰余は符号付き・符号なし32/64 bit の小規模入力と最小値・最大値を比較し、C++ 側は UBSan を使う。独立した Python の0方向丸めの計算とも比較し、符号混在の通常算術変換、ゼロ除算と最小値/−1・最小値%−1の拒否を検査する。演算、比較の境界、除算から剰余への変更で元の結果を要求する Lean 検査が失敗することも確認する。未対応構文の拒否は独立した小ケースで検査する。

共有基盤は `verifier/support.toml` に Lean モジュール・Python モジュール・検査・文書を登録する。`Proofs.lean` の import と登録を照合し、未登録の証明ファイルの拒否は維持する。全公開検証の `all` モードで共有検査を実行し、Lean ビルドと `leanchecker`・CI の公理監査は共有モジュールも対象にする。部品ごとの bridge パスの一意性制約は撤廃したが、既存2部品の実際の bridge は移行前のままである。

明示的なキャストの専用検査では、bool・符号付き/符号なし32 bit・符号付き/符号なし64 bit の5型の各組み合わせについて3構文（計75関数）を生成し、同じ変換の IR 一致、最小値・最大値・32 bit 境界を含む結果と拒否範囲を確認する。C++ の UBSan 実行と Python の型変換の独立計算を比較する。範囲外の符号付き変換は C++ の実装定義の値との一致を主張せず、モデルが成功を返さないことを確認する。int へのキャストを bool に変更すると、元の値を要求する Lean 検査が失敗することも確認する。既存の型変換と費用の Lean 定理を使い、新しいキャスト固有の公理を追加しない。

参照更新・状態・分岐と基本ループは別の共有モジュールで扱う。引き続き配列・STL 契約、未対応の制御構文、持ち込み部品の全入力証明、既存2部品への移行、公開登録の共通 bridge 対応を進める。途中のスカラー対応だけで全件検証の完了とはしない。

リテラル同士の左シフトは、幅内の非負のシフト量と対応整数範囲を検査して乗算へ変換する。仕事量は元の二項式と同じで、変数のシフトと実装依存の signed 結果は拒否する。標準 assert の条件内だけで使う短絡評価は [状態変換器](state_converter.md) を参照する。


## 対象コンパイラの signed 整数変換

既定の `--signed-conversion checked` は、従来どおり signed の表現範囲外への変換を拒否する。[C++17 ドラフト N4659 の 7.8 [conv.integral]](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2017/n4659.pdf) では、この変換は実装依存である。`--signed-conversion gcc13.3-lp64-twos-complement` は GCC 13.3.0、x86_64-linux-gnu、C++17、LP64 の32/64 bit整数幅・8 bit byte・64 bit pointer を検査してから選択する。別の対象や ABI は拒否する。GCC のこの対象での変換を、幅の剰余を signed の範囲へ復号する契約としてモデル化し、境界値を固定コンパイラの C++ 実行と比較する。この契約は C++ とモデルの意味対応の信頼前提であり、任意の C++17 処理系に対する保証やコンパイラ自体の形式検証ではない。

`Expr.targetCast` は変換にだけ用いる。入力の型の範囲を対象型がすべて表現できる場合は、既存の `Expr.cast` を保持する。整数の加減乗算、単項マイナス、除算・剰余は従来の検査付き規則を使い、signed の範囲超過・ゼロ除算・MIN/-1 と MIN%-1 を失敗として扱う。複合代入の最後の格納型への変換にも同じ規則を適用する。unsigned と bool の変換規則は既存のものを使う。

`CppTargetCast` は、任意の正の幅と整数について復号値の範囲と表現可能な値の保持を証明する。32/64 bit の対象変換が必ずその型の範囲内を返すこと、および64 bitの復号が既存の signedDecode64 と一致することも示す。`Expr.eval_work` は新しい変換でも仕事量が式のノード数に一致することを証明する。対象変換の選択は IR と生成 Lean のコメントに記録し、既定のモデルを黙って差し替えない。

`tests/test_target_cast_ir.py` は C形式・static_cast・関数形式の144ケース、局所初期化・代入・引数・返却・複合代入の28ケースを、独立した整数剰余の期待値と生成 Lean、UBSan 付き C++ で比較する。既定の範囲外変換拒否、別の対象の拒否、対象変換を選んでも signed 算術のオーバーフローを拒否することを確認する。元 signed floor_sum の689ケースも同じ経路で比較し、全入力証明とは区別する。

## スカラー関数の展開（`[[gnu::always_inline]]`）

呼び出される側の関数に `[[gnu::always_inline]]` を付けると、共通生成器（`verifier/inline_ast.py`）はその呼び出しを呼び出し側の文として展開する。値の引数は新しい局所変数、最後の `return` の式は呼び出しの値を持つ局所変数になる。付けないスカラー関数は従来どおり `invokeScalar`（別の `LoopProgram` を呼ぶ形）になる。展開できる条件は vector を取る関数の展開と同じ（再帰・途中の `return`・ループ条件や短絡演算の中の呼び出しは拒否）。展開した場合、補助関数も単独の関数として生成されるので、公開するなら補助関数ごとに証明が要る。`tests/test_inline_scalar_calls.py` が確認している。

## スカラークラスの委譲構築と型だけの宣言（2026-11-05）

スカラー値への消去は、helperクラスも含めてtrivial copy/move/dtor、baseなし、bitfieldなしをクラス全体で確認する。独自copy/dtorや格納幅をidentityで消さない。これらの意味を持つ元CPPのAPIを削るのではなく、object-state/lifetimeの変換経路で扱うまで消去経路では未対応として拒否する。

単一fieldの直接構築でbodyが状態を変更したりfieldを参照する場合は、初期化式の値を先に局所fieldへ保存し、その後でbodyを実行する。bodyのthis/fieldへのアクセスと戻り値はその同じ局所fieldを使う。bodyが引数を書き換えた後に初期化式を再評価しない。引数変更、field変更、両方の変更、body内のhelper構築、初期化式内の呼出しをC++/UBSanと生成モデルの具体例・固定独立kernelで比較する。既存の純粋な初期化と引数に対するassertだけの経路は維持する。

単一スカラーfieldの消去経路では、同じクラスへの空bodyの委譲構築を、その初期化式を返す関数へ変換する。委譲先の呼出しは既存のinlinerを通し、生成された一時セルとassertを残す。trivial copy/move/dtorを確認し、後処理を持つ一時値や非空bodyは拒否する。これにより、初期化後のbodyや破棄を実行せずに消すことを避ける。

複数スカラーfieldの投影経路では、同一クラスへのtrivialなコピー/移動と、引数なし静的factoryの単一returnを辿る。再帰を検出し、委譲/対象構成子のbodyは空、各fieldの初期化は整数literalと許可したcastだけであることを全件確認する。他fieldの副作用や失敗する算術を落とさないため、未使用fieldに加えて、置換前の全構成子引数もliteral-onlyと確認する。未使用引数のrandやゼロ除算も消さない。一般の投影では、全fieldとbodyのどちらからも参照されない構成子引数も、返却前の局所宣言として評価する。例えば未使用の7/nはn=0でfaultとなり、成功したfield値だけを返すことはない。一般の投影でも構成子引数/field初期化式の呼出し・書込みや、bodyの状態変更は未対応として拒否する。これらは全fieldを順に構築するobject-state経路へ接続する残件である。この経路では値/既定構成子の各fieldも検証対象として出力する。3field、異なる整数幅、改名とnamespaceを変えたクラスも回帰に含める。クラスの型名はClangのdelegating initializerに含まれる修飾済み型から得る。

関数body内のusing/typedef、属性のない関数の前方宣言、コンパイルで成立を確認したstatic_assertは実行時命令を持たないため取り除く。型の宣言でもVLAやtypeofのように評価を伴い得る形は取り除かず、未対応として拒否する。constexpr ifを消せるのは、runtime initと条件変数がなく、残った両分岐が空blockの場合だけである。通常if、実行する宣言/文、属性を持つ関数宣言は残す。

元のhidden friendとnamespace関数テンプレートが併存する場合は、別の生成名で両方を検証する。具体化を促す非型テンプレート引数のwitnessは型だけの宣言で構成し、実行時の局所変数を作らない。`Group`の公開CPPは元のfriend/委譲/return形式を保ち、LL以外のTへwitnessの条件を加えない。証明対象は明記した整数具体化とfield投影であり、任意Tや完全なC++ object/lifetime ASTを扱うこととは区別する。

`tests/test_scalar_class_delegation.py`は、原本との構築event列比較、上記の受理/拒否、生成された構成子の具体例、一般の構成子定理とfriendプログラムの一致を検査する。Leanの型検査に加え、基礎3公理だけを許可した固定nanodaの通常stack/2threadsで独立検証する。
