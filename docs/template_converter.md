# 主テンプレートの構文 IR

`verifier/template_ir.py` は未具体化の FunctionTemplateDecl から、型パラメータを残した IR を生成する。名前・ソースハッシュやアルゴリズム名でモデルを選ばない。公開用の既存 state_ir / state_bridge とは分離した実験経路であり、組み込み整数族の Lean 具体化規則は実装したが、ユーザー定義型を含む全入力の結果・安全性・費用の証明と公開ゲートへの接続は未完了である。

## 現在の対応範囲

深さ0の、既定引数・パックを持たない名前付き型パラメータ、lvalue 参照パラメータ、組み込みスカラーの返却型を扱う。変数は Clang の宣言 ID からスロットへ、型パラメータは宣言の index へ対応する。型名・変数名の改名は同じ IR になる。

文は block、if/else、参照先への単純代入、return、空文。式はパラメータ参照、整数・bool リテラル、組み込み整数変換、比較6種。型依存の比較・代入と if の条件変換を未解決として記録する。using namespace std 等により UnresolvedLookupExpr を持つ演算子呼び出しも認識し、Clang の lookup 候補の正規化情報を保持する。この情報だけでユーザー定義型の ADL・演算子・一時オブジェクトの寿命を解決したとは扱わない。

値パラメータ、依存する返却オブジェクト、局所オブジェクト、ループ、一般の呼び出し、複合代入、volatile、rvalue 参照、既定型引数、パック、非型引数、特殊化・具体化が混在する入力、関数の追加修飾等は拒否する。未対応の演算を組み込みの純粋な演算や一定費用へ置き換える経路はない。

## 組み込み整数への具体化

`specialize` は現在のスカラー変換器と同じ bool、int、unsigned int、long、unsigned long、long long、unsigned long long の正規化された型名だけを受け取る。クラス・enum・浮動小数点・short・別名の型名は受け取らない。LP64 の幅と C++ の整数の rank を区別し、bool の int への整数昇格、比較の通常の算術変換、代入・返却型への変換を生成する。long と long long の幅が同じでも、必要な変換ノードを省略しない。

具体化は既存 state_ir と同じ型付きの関数 IR を返す。この経路の組み込み型引数ではユーザー定義演算子を選ばず、比較の結果は bool として解決する。クラス型引数にはこの解決を適用しない。checked が既定で、範囲外 signed 変換はモデルが失敗する。明示した gcc13.3-lp64-twos-complement も既存の検査・変換規則へ渡す。符号が異なる比較は変換後の値を比較するため、常に数学的 min/max と一致するとは主張しない。

## 生成物と検査

`experiments/verification/template/update_extrema_primary.json` は候補ヘッダの2主テンプレートから生成した IR の全文で、テストが毎回再生成して照合する。証明済みの Lean モデルではない。

`tests/test_template_ir.py` は bool と32/64 bitの7種類、左右49組について2ヘルパー計98関数を具体化し、Clang が実際に具体化した関数から既存 state_ir が生成した IR と全項目を照合する。checked と明示した GCC 変換契約の両方を検査する。元の2系列でも2ヘルパー各49組、計196関数を比較する。型・変数の改名、比較変更が IR へ反映されること、別名の比較・更新テンプレートも同じ規則で生成されること、未対応型・構文と既存公開経路への未解決テンプレートの混入の拒否を確認する。

これらは生成対応の検査である。整数族の実行証明は下記の IntegralExtremaExecution で扱う。ユーザー定義型の演算と寿命・所有権の契約、主テンプレート全体の証明、公開は引き続き必要である。整数族の証明を任意の型を持つ主テンプレート全体の証明済みとして台帳へ反映しない。

```sh
python3 verifier/template_ir.py experiments/verification/template/update_extrema.hpp
python3 tests/test_template_ir.py
```

## Lean 上の整数族の具体化

`Proofs/CppTemplate.lean` は7種類の整数型、rank、bool の昇格、通常の算術変換、checked / GCC 契約の cast を定義する。型パラメータを残した TemplateProgram から型付き StateProgram への具体化を構造的な再帰で行う。引数数の不一致、型パラメータの欠落、存在しない代入先、読み取り専用の代入先は None となる。比較の共通型の対称性・rank・昇格と同じ型への変換等の6補題を Lean で証明した。

`Proofs/IntegralExtrema.lean` は候補 C++ の主テンプレート IR から emit_lean で生成する。`Proofs/IntegralExtremaShape.lean` は任意の整数型の組・両変換契約で2ヘルパーの具体化が存在することと、従来の4生成モデルとの定義上の一致を証明する。クラス型の演算子 lookup を整数の規則で解決する経路はない。

`tests/test_template_lean.py` は生成ファイルの全文を照合し、98具体化を両変換契約で実際の Clang AST から生成した StateProgram と照合する。計196個の等式を rfl で Lean カーネルが検査する。これはプログラム形状の一致である。実行の証明は下記の別モジュールで扱う。主テンプレートの証明済み・公開済みのフラグは保持する。

```sh
python3 tests/test_template_lean.py
```

## 整数族の呼び出し全体の証明

`Proofs/IntegralExtremaExecution.lean` は型の組 left/right、変換契約 policy、min/max の選択、任意の caller メモリと参照アドレスを量化する。source_schema は主テンプレートから具体化したプログラムが、実行証明の対象と定義上一致することを示す。call_correct は値レベルの通常の算術変換後の ac/bc を比較し、更新する場合だけ b を左辺の型へ変換して格納することを証明する。符号混在では数学的な大小と一致するとは限らない。checked では更新する分岐の signed 変換が表現可能であることを要求するが、実行しない代入の表現可能性は要求しない。

common_conversion_total は比較の変換が有効な入力の全範囲で成功することを証明する。target_conversion_total と call_target_total は明示した GCC 契約に対して、左右7型のすべての組・全範囲の値で呼び出しが正常終了し、仕事量12以下・追加領域7以下となることを示す。同じ型の call と同一セルへの alias も全7型・両契約で扱い、数学的 min/max と一致する。同一セルへの呼び出しは0を返し、メモリを変更しない。

result_frame は更新先の新しい値、メモリ長、更新先以外のすべてのセルを保持することを示す。未参照セルは型の有効性を仮定しない。C++ の参照は初期化済みで寿命内のオブジェクトを指し、各パラメータの実際の C++ 型で合法にアクセスできる必要がある。LP64 で幅が同じ long / long long を用いた不正な型の参照キャストを、この抽象セルの証明で正当化しない。

`tests/test_integral_extrema_execution.py` は49型組の境界入力196組で、両ヘルパー・両契約の784 Lean 呼び出しを独立した Python の整数計算と照合する。GCC 契約の392 C++ 呼び出しも UBSan 付きで一致する。checked の更新時の変換を拒否する20件も確認する。同一セルの参照は全7型の境界値で92 Lean 呼び出し・46 UBSan 付き C++ 呼び出しも照合する。ソースを再生成して実行証明を再検査し、比較2種・代入・返却値の4改変を拒否する。これらの有限テストと、Lean の任意の型・値・メモリに関する証明の範囲を区別する。

```sh
python3 tests/test_integral_extrema_execution.py
```

この範囲で組み込み整数族の呼び出しの結果・正常終了・モデル内の型/境界検査・仕事量・領域を扱った。ユーザー定義型の演算、例外、一時オブジェクト、寿命・所有権の契約と主テンプレート全体の公開条件は未完了である。

## 具体化したテンプレートの内部呼び出し

`state_ir.py` は、選択した AST の FunctionTemplateDecl から実際に具体化された FunctionDecl を取り出し、通常関数と同じ呼び出し解決へ登録する。型パラメータだけの主テンプレートであること、具体化の TemplateInstantiationPattern がその主宣言を指すこと、型引数の個数と対応するスカラー型を検査する。未具体化、既定型引数、パック、非型引数、明示的特殊化は拒否する。選択した AST に本体がない呼び出しは従来どおり拒否する。

呼び出しは Clang が選択した FunctionDecl の ID で解決し、実際の具体化済み本体・引数型・結果型を invoke へ生成する。テンプレート間、通常関数からテンプレート、テンプレートから通常関数への呼び出しは同じ規則を使う。参照・値の検査、引数の評価順序、ループの実行枠、再帰の拒否も共通である。名前だけで主テンプレートの意味を仮定しない。同じ名前の通常関数とテンプレートも、出力名が衝突しなければ選択された宣言を区別する。

公開用の具体化は従来の型引数を含む名前を持つ。呼び出し解決用のキャッシュはその名前へ変更せず、呼び出し先の本体を保持する。coverage は引き続き concrete_instances_only であり、実際に具体化した型・構文の検証である。`template_ir.py` の未具体化の主構文・整数族の証明とは別経路で、一般の主テンプレート、ユーザー定義型、全入力の結果・停止・費用と公開条件の証明を代替しない。

`tests/test_template_call_ir.py` は7テンプレートを実際に具体化し、テンプレート間の値呼び出し、参照条件を持つテンプレートのループ、同一セルの参照、元の chmin/chmax への通常関数からの呼び出しを73ケースで生成 Lean / 独立した期待値 / UBSan 付き C++ と照合する。signed 範囲超過の拒否、unsigned のラップ、改名の不変性、演算変更による結果不一致、同名の通常関数とテンプレートの呼び分け、再帰・定義欠落・明示的特殊化・非型引数・未対応の複合参照式の拒否も確認する。既存の整数族の実際の Clang 具体化との照合は維持する。

```sh
python3 tests/test_template_call_ir.py
```
