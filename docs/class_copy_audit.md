# 暗黙クラスcopy構成子のAST監査

`verifier/class_copy.py`は、元ヘッダーを変更せず、const参照からcopyを実体化するwitness翻訳単位を固定Clangでコンパイルする。アクセス制御の無効化は使わない。結果のcoverageは`member_identity_only`であり、**Lean実行モデル生成やクラスcopy全体の検証成功ではない**。共通評価器とUF状態モデルの同値証明は別途追加したが、監査計画から直接評価器のprofileを生成する経路を追加した。call siteとの接続は未完了である。

## 実体化と元ソースの所有関係

witnessは元ヘッダーを唯一のforced includeとして読み、指定型のconst参照から同型のローカルをコピーする。型名はC++の修飾識別子に限定する。witnessのnamespace・関数・変数名は毎回異なる識別子とし、元コードの通常の名前と衝突させない。

`ast_stream.forced_class_records`は、修飾名が一致する完全な原class/structだけを抽出する。Clangの即時include元が`<built-in>`であること、元ファイルの位置、macro展開でないことを確認する。元ソースがincludeした別ヘッダーのclassを原classの定義として扱わない。通常の`direct_location/direct_functions`がincludeされた宣言を拒否する方針は変更しない。

元ソースの絶対パスと内容hash、同じdumpの識別子をclassと標準宣言に結び付け、修飾クラス名も実体化時の値へ固定する。実体化中または監査前の内容変更、別ソースへの付替え、別dumpの標準宣言との混在は拒否する。これらの識別子は生成IRの意味を選ぶ名前ではなく、その監査呼出し内の証拠である。

## 現在の監査プロファイル

対象は、基底classやvirtual機能を持たないclass/structの、先頭のflat scalar vectorと後続のscalarフィールドである。scalarは既存`scalar_ir.TYPES`の固定整数/bool型に従う。vectorの要素にはboolを含めない。型aliasはClangのdesugaredQualTypeで解決する。field名、class名、scalar件数をUF固有の定数で選ばない。

copy構成子は、const同型参照を1つ受け取り、isImplicit、isUsed、explicitlyDefaulted=defaultを持つ原宣言でなければならない。実体化された初期化子を全fieldの宣言順で持ち、bodyが空であることを確認する。ヘッダー単独での宣言だけをbodyの代わりにしない。実体化後に計算されるnoexcept(false)の文字列だけでcopyを選ばず、パラメータ型と宣言を調べる。

各初期化子のFieldDecl IDと型・名前を原fieldに照合する。vectorの元MemberExprとscalarのLValueToRValueは、その同じfieldを、同じconst source ParmVarDecl IDから直接読む必要がある。別field、別source、並べ替え、任意cast、追加bodyを受け入れない。const/mutableと型aliasによる資格変換を扱い、コピー先のwritableは元パラメータのconstnessではなくfield宣言から決める。

標準vectorコピーは、共有`vector_stl.audit_vector_nodes`でpristine primary、default allocator、使用されたhelper specialization、コンストラクタの同一dump内の宣言IDを監査してから印を付ける。flat scalar vectorのconst参照copyだけを扱う。mutable vectorの資格変換でClangがconst vector<T>という非修飾名を出す場合も、NoOpの元のcanonical std::vector<T>型を照合する。古い監査印を入力に残して信用しない。

## 未対応と信頼境界

複数vectorクラスの構築・メソッド生成用には、`audit_copy_record(..., vector_anywhere=True, multiple_vectors=True)` が各flat vectorを元宣言順に監査する。件数制限だけを明示的に外し、全fieldの同一TU・型・ID・初期化子・元sourceの監査は維持する。既定のcopy評価器用プロファイルは1vectorのままであり、この監査オプションから複数vectorのclass copy実行を証明済みとは扱わない。

user-defined/明示defaulted/deletedなcopy、user-declared destructor、基底/virtual、attribute、bitfield、volatile/reference field、先頭以外のvector、複数vector、nested vector、vector<bool>、custom allocator等はこのプロファイルで受理しない。テンプレート型名もwitness APIでは未対応である。元APIを削って対応済みにせず、該当classは未完了としてexperimentsに残す。

`nested_ir.lower_source`は監査済みflat scalar vectorのローカルcopyを新IR `copy_vector`へ変換し、通常NStmt.copyVectorから実行する。監査計画から直接評価器のprofileを生成する経路とUFモデルへの同値証明を追加した。call siteのclass layout/const view、AST fieldとObjectRef slotの対応、copy/move代入とmoveは未完了である。標準ライブラリ結果モデルとC++→Lean意味対応の信頼前提は`trust_policy.md`および`vector_copy_contract.md`に従う。新しい公理は追加しない。

## 共通コピー評価器とUFモデルの同値

`Proofs/CppClassCopy.lean`の`Profile`はvector要素型・コピー先のwritable・宣言順のscalar型/権限を持つ。`copyClass`はsource `ObjectRef`からvectorを独立所有領域へコピーし、typed scalarを読んで新しいcell/bindingへ保存する。source scalar slot数とprofileのfield数が一致しない場合や型/slot不正は失敗する。コピー先の権限はprofileから決め、const元の権限を引き継がない。既存constructor finishのscalarBindings/scalarLocations/referenceを再利用する。UFへのimport依存はない。

`Proofs/UfClassCopyBridge.lean`の`copy_equiv`は、任意NState/Layoutについてi32 vectorとwritable i32 scalar2件の共通評価器が既存copyReceiverの結果とwhole stateで一致することを証明する。失敗も含むOption結果の等式で、Strongやscalar nとvector長の一致を前提にしない。work/peakも同じstateの成分なので同じ結果になる。これは直接評価器どうしの同値で、通常NProgramのprepare/body/finish経由のコストへは適用しない。

`tests/test_cpp_class_copy.py`は任意state/layoutへの一般適用、実構成子のコピー結果、const元、scalar0/3件と混合権限、slot/型/件数不正、scalar n/countがvector長と異なる状態の値保持を確認する。AST fieldの役割とObjectRef slot順の結び付け・call site const viewは未完了であり、監査結果のcoverageは引き続きmember_identity_onlyである。

`emit_class_copy`はsourceを再監査して、宣言順fieldNames、qualifiedClass、source SHA256、型/permission profileとcopy関数をLeanへ生成する。raw planを引数として信用せず、生成前後のsource hashも照合する。dumpごとに変わる宣言IDは出力へ埋め込まない。名前metadataは意味を選ぶ分岐ではない。生成されたUF profileがbridge profileと定義的に一致することと、生成copyの任意state/Layoutに対する同値をLeanで検査する。別名Packet、long long vector、const vector/long、unsigned/bool/mutable、scalar3件も実AST→生成Leanの型/順序/permissionを確認し、繰返し生成の決定性とnamespace不正拒否を検査する。これはcall siteを下げる生成IRではなく、source ObjectRefを引数に取る直接評価器である。

## コンパイラが解決した標準include profile

`vector_stl.translation_unit`は固定ClangのAST取得と同じinvocationでheader-include-format=json/filtering=only-direct-systemを使い、user→systemの実読み込み境界を順序付きで記録する。forced include、quoted wrapper、macro include、inactive conditional、include searchのshadowingをソース行のregexで推測しない。report.sourceは実unit（copyの場合はwitness）に照合し、profileは全std rootsで同一でなければならない。

replay対象は実在し、実解決先が固定GCCのsystem roots内にあるヘッダーだけ。ユーザーwrapperをpristine再現入力にしない。vector-only pristine比較で不一致の場合だけ実profileを再現し、primaryを引き続き厳密照合する。標準helper/allocator/iterator/同TU宣言ID監査は維持し、user macroでprimaryが変わった場合をpristine成功として扱わない。新テストはordered reportのorigin/schema/許可パス、active macro/conditional/quoted wrapper/include_next shadow、macro改変primaryと欠落・不整合・user replay profileの拒否、旧sourceの生成Lean同値を確認する。

## コピー元の式を評価するstatement用モデル

`CppFrameCopyCore`へcopyBinding/copiedFrame/copyVectorの純定義を分離した。既存の完全修飾名と定義bodyは維持し、証明はCppFrameCopyへ残す。低層coreはCppNestedCopyだけへ依存するため、NStmtを定義する層から利用できる。copyOwnerは解決済みownerのobjectとcopyRootを検査して同じfresh copyを作る。copy_vector_ownerは成功resolveの後では両入口のOption全結果が同じと証明し、copy_owner_rebindは一時bindingを除いたprefixへfresh bindingを追加する同値を証明する。

`CppCopyStatement.run`はsource Container.eval→Frame.resolve→一時bindingのrelease→owner copy→新slot追加→statement chargeの順に実行する。rowを選ぶ式が作るtemporaryを先に解放し、コピー先bindingは保持する。`CppCopyStatementFacts.completes`は型付きsource評価/resolve、flags長整合とsupported型から実終了とreleased frameのExtendsを構成する。keeps_readはreleased frameで成功した全旧参照を保持し、keeps_scalarはnextの全旧成功scalarCellを保持する。

result_costはsource評価後のnextを基準に、work増分=source要素数+2、nested live増分=source要素数+1、storage peak=max旧peak(旧live+source要素数+2-base)を証明する。source評価のwork/peakはnextへ含まれ、直接copyClassのコストと同一視しない。NStmt.copyVectorはこの同じrun定義を呼び、nested IRのcopy local宣言から生成する。field/slot対応、const instanceのmutable field、scope終了解放、全caseの一般証明を揃えるまでC++ class copy全体の検証済みとはしない。

`tests/test_cpp_copy_statement.py`はreadonlyな親からscalar変数を添字にrowを選び、temporaryが消えてfresh bindingだけが残ること、readonly/mutableコピー先、旧ref/scalar保持、相互の書込み独立、空/不正source、容量17から2へのコピー、正確なlocal/row work、非零baseline・過去peakの保持を検査する。固定GCCのC++ UBSan実行でもconst親/動的添字/constコピー先と書込み独立を照合する。モデル検査とnative有限照合をC++全入力の意味保存とは扱わない。

## 通常NStmtとローカルvector copyの生成

`NStmt.copyVector`はsource Container、要素型、コピー先writableを持ち、既存CppCopyStatement.runの同じ定義を実行する。定義は低層CppNestedProgramへ移し、CppCopyStatement.statement_runは両入口の全状態同値をrflで示す。既存の全依存モジュールを新variantで再ビルドし、scalar/no-resize等の限定プロファイルが新しい確保命令を誤って受理しないこともcase証明の再型検査で確認する。

nested_irは同TUの標準copy監査印を持つ、引数1つのflat scalar vector構成子だけを生成する。sourceはローカルまたはnested rowからのContainerとして先に解決し、要素型一致を確認してからコピー先slotを登録する。自己初期化など未登録sourceは拒否する。コピー先constは宣言から決め、source readonlyを流用しない。nested/bool vectorのコピーやallocator明示overload等は引き続き未対応。クラスObjectRef/field-slot/const instance mutable fieldの呼び出し側生成は別義務。

`tests/test_vector_copy_ir.py`は同じC++関数をASTから生成し、readonly入力のmutableコピー、readonly親のscalar引数を添字とするrowコピーとconst先、明示blockスコープのコピーを通常callFuelで実行してnative UBSanと照合する。旧buffer/ref/binding/slot/scalar memory/scopeの保持と、ローカル所有領域が返却後tombstoneへ退去することを確認する検査である。名前変更と未対応shape/自己初期化の拒否も扱う。有限照合とstatement成分の一般補題をC++クラス全体の意味保存完了とは扱わない。

生成copy関数のvector引数には、具体的CppNestedCallでrootに加えて行headerの借用を追加した。元参照のresolveと権限を確認し、同じaddress/epochを保持して新aliasを再resolveする。tests/test_vector_copy_ir.pyはrootとchildの両入力を維持し、borrowed write、readonly権限昇格拒否、stale headerとowner不一致拒否も検査する。関連するframe・ピーク・束縛存在の一般補題は[vector_contracts.md](vector_contracts.md)を参照。純粋root Family解決器のrow自動証明やクラス全呼出しの完了は別義務。

## 同じ翻訳単位からの構成子field layoutとexport生成

`verifier/class_copy_layout.py`はsourceを改めてコンパイルしたcopy witnessの同じrecord/標準rootsから、暗黙copyの監査とユーザー定義構成子のstageを作る。構成子のfield metadataには元FieldDecl ID・宣言型・mutableを保持し、copy側のID/宣言順/型/宣言permissionと一致することを確認してから、lowererが実際に割り当てたslotへ対応させる。名前だけでslotを決めない。初期化式の補助関数呼出しで一時slotが入る場合や、fieldと同名のlocalがある場合も区別する。従来のconstruction_fieldsのname/slot出力は維持する。

`lower_class_layout`のclass_fieldsはordinal/slot/kind/element/declared_writable/mutableを持ち、class_exportは実vector slotと宣言順のtyped scalar slotsを持つ。`emit_class_layout`はこれらからconstructFuelのexport引数を生成し、CppConstructorFinishのObjectRefへ接続する。stage/補助関数はStages namespaceへ置き、copy/profile等のメタデータとの名前衝突を避ける。source hashは生成の前後で照合し、dumpごとの宣言IDはLean出力へ埋め込まない。

コピー先のprofileFor(targetConst)は、各fieldのdeclared writableと`!targetConst || mutable`の両方から権限を決める。通常のprofile/copyとconstProfile/copyConstを生成し、const sourceの権限を新しいコピー先へ引き継がない。共通のmethod loweringもconst methodでmutable fieldを一律readonlyにせず、declared constを二重に付けない。構成子stageではdeclared const scalar/vectorの基本型を正しく分類する。普通のbool scalarはvector<bool>の未対応とは区別する。

`tests/test_class_copy_layout.py`は、生成UF構成子/exportと既存検証入口の全状態同値、および共通copyとUF bridgeの全状態同値をLeanで確認する。別名Packetではconst stamp、mutable unsigned/bool、fieldと同名のlocal、nonconst元からconstコピー先への構築とconst methodでの書込みを通常評価器とnative UBSanで照合し、元の値が保持されることを検査する。declared const vectorのconst methodと、profileという補助関数の初期化呼出しによる一時slotも扱う。

この経路の範囲は、既存copy監査と同じflat scalar vectorが先頭でscalar fieldsが続くprofileと、生成可能な明示的構成子stageである。暗黙default構築、任意のclass copy call site、一般の構築先const view、assignment/move、全クラスのscope退去や全入力の意味保存は別義務であり、クラス全体の検証済みとはしない。原sourceのAPIを狭めたり、この追加だけで公開へ昇格したりはしない。

## 通常命令列としてのmember copy

`Proofs/CppClassCopyCommands.lean`はvectorのcopyVectorに、宣言順のscalar初期化を続ける。各scalarは元のslotを変数として読み、型を保つ新cell/bindingを作る。実行時の値をliteralへ置き換えず、元のaliasが指す現在の値を読む。runCopyFuelは開始状態で元scalar fieldsを検証する。不正な元slotが後から作ったtarget slotとして存在するようになる例を防ぐためで、後続の読取りが成功したことだけから元objectの正しさを推定しない。

copy_commands_completeは、元vector slotの解決、flagsの整合、要素型の対応と初期scalar読取りの成立から、k件のscalar fieldsを持つ命令列がfuel k+2で正常終了することを証明する。実行全体の成功を前提にしない。UFのStrongやnとvector長の一致も要求しない。全旧成功scalarCell/vector参照を保持し、結果のframe、memory、bindings、slots、scope、baseMemoryは直接copyClassのfinishと一致する。

資源カウンタは同一視しない。整形式のvector状態ではwork増分はn+2k+3（nはコピー元vectorの要素数）。scalar peakはmax(旧scalar peak,旧scalar live+1+2k)以下、storage peakはmax(旧storage peak,旧vector live+n+2-baseSpace)、outer peakは旧outer peakと両成分の上界の和のmax以下となる。過去のpeakと非零baselineを含む抽象資源の定理であり、実時間や実byte数の測定値ではない。k=0では変数評価の一時領域が残るため、直接評価器とのpeak差も検査する。

emit_class_layoutは同じ監査済みprofileからcopyCommandとrunCopyFuelの入口も生成する。tests/test_cpp_class_copy_commands.pyはscalar0/2件、初期sourceの不正slot、旧参照保持、work/peak差を確認し、実ASTのlong long/unsigned/bool profileでは構築→通常命令列によるconst copy→const methodでのmutable更新と元保持をnative UBSanへ照合する。これらは既存モデル内のmember copyと生成バックエンドの接続であり、任意のC++ class caller ASTの受理、全method呼出しの境界、assignment/moveの完了ではない。


## メソッドの呼出し境界と呼出し元の制御

`Proofs/CppNestedInvoke.lean`のinvokeScalarFuelは、生成済みNProgramのprepare/body/finishをcallFuel経由で実行し、scalarまたはboolの結果を呼出し元の新しいreadonly localへ保存する。calleeのreturnはこの境界で消費し、呼出し元のreturn/breakにはしない。finishによる型検査、callerのscalar更新、callee scopeの退去をそのまま使う。vector/unitの戻り値はこの追加adapterの対象外であり、従来のcallFuelの対応範囲を変更しない。

invoke_of_stepsはprepare、実body実行、finishからadapterの正常終了を導く。call_scalar_facts/invoke_resultは結果型のvalidityと、元callerのslot数に対応する新cell/bindingのreadonly参照先を証明する。save_result_keeps/vector_slotは追加前の成功scalar読取りとvector slotを保持し、frameは変わらない。calleeが変更した値はfinish後の値を使う。追加保存のworkは1、scalar peakはmax(終了直後の旧peak, memory長+1-baseMemory+bindings長+1)、outer peakは旧outer peakとscalar/storage成分の和のmaxである。これはcallFuel本体の計算量を省略した全体の定数時間主張ではない。
