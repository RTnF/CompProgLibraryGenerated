# dynamic_modint

`cp::DModInt` は、実行時に決まる法 `m`（1 ≤ m < 2^32）での剰余整数である。`experiments/library/cpp/modint/dynamic_modint.hpp` の `DynamicModInt` から作った。値は `[0, m)` に正規化して持つ。

元のソースからの変更（検証できる形にするために書き換えた）:

- 法 `m` を静的メンバー（`DynamicModInt::m`）ではなく、各値のフィールドにした（検証器がグローバルな可変状態を扱えないため）。演算は左の被演算子の法を使い、両方の被演算子が同じ法を持つことを前提にする。
- 複合代入演算子（`+=` など）とフレンド演算子を、新しい値を返すフレンド関数 `add`・`sub`・`mul`・`neg`・`equal` と、冪乗 `power(a, e)`、逆元 `inv(a)`（法が素数）、除算 `div(a, b)` にした。冪乗・逆元・除算は `library/pow_mod.hpp` を呼ばず、そのループを関数の中に書き下した（検証済みの関数は別の関数から呼べないため。証明は `Proofs/ShiftN.lean` で `pow_mod` のループの補題を再利用している）。
- 符号付き・符号なしの型のテンプレートコンストラクタ、入出力、`factorial` などの関数は含めていない。

結果（`Proofs/DynamicModIntCall.lean`、一般の入力について証明）: 前提は `0 < m < 2^32`、被演算子の `x`・`y` は 32 bit 符号なし整数（正規化済みの値 `x`, `y` < `m` はすべての前提を満たす）、法が同じこと。演算ごとの追加の前提は下のとおり。
- `add(a, b).x = (x + y) mod m`、`sub(a, b).x = (x + m - y) mod m`（前提 `y ≤ x + m`）、`mul(a, b).x = (x * y) mod m`、`neg(a).x = (m - x) mod m`（前提 `x ≤ m`）、`equal(a, b)` は `x = y` のとき 1、それ以外は 0。各結果の `m` は元の `m` のまま。
- `power(a, e).x = x^e mod m`（`e` は 64 bit 符号なし整数、`x` は正規化されていなくてもよい）。`inv(a).x = x^(m-2) mod m`（前提 `m ≥ 2`、`x ≠ 0`。法が素数のとき真の逆元）。`div(a, b).x = x_a * (x_b^(m-2) mod m) mod m`（前提 `m ≥ 2`、`b.x ≠ 0`）。いずれも結果の `m` は元の `m`。
- 時間は `add`・`sub`・`mul`・`neg`・`equal` が定数、`power`・`inv`・`div` が `O(log e)`（モデル上の仕事量は高々 3200 程度）。64 bit の中間値は 2^64 未満であることを証明している。

定理に含めていないこと: コンストラクタ `DModInt(m, x)`（2 フィールドのクラスのコンストラクタは変換器が関数にしない。C++ のテストで `x % m` を確認している）、負の指数（元の `pow(ll)` は負の指数で逆元を取る。ここでは `power` は符号なしの指数）、前置・後置の `++`/`--`、入出力。C++ のテストは `tests/dynamic_modint.cpp`（極端な法を含む 10 個の法で、128 bit 整数による基準と比較する）。
