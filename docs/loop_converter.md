# ループの共通変換と停止条件

`state_ir.py` の文変換に、`while` と基本的な `for`、捨てられる値を持つ文としての整数 `++`・`--` を追加する。変換規則は構文と型に対応し、関数名やソースハッシュには対応しない。`for` は初期化、条件付きループ、反復本体、更新式に落とす。初期化した変数のスコープと、本体の反復ごとのスコープを保つ。return した場合は更新式を実行しない。

同じ `Stmt`・型・メモリ・式・費用契約を使い、ループを持つ生成関数だけを `LoopProgram` とする。ループのない関数の生成結果と既存の全入力証明は維持する。通常の `StateProgram.call` に暗黙の反復上限を付けてループを成功扱いする経路はない。

## 実行結果と停止

`Proofs/CppLoop.lean` の `runFuel` と `LoopProgram.callFuel` は明示的な自然数の実行枠を取り、次の結果を区別する。

- `finished`：返り値、更新後のメモリ、抽象仕事量と追加領域を伴う正常終了。
- `fault`：参照・型・整数演算・return 等のモデルの検査失敗。実装定義の範囲外変換等の前提範囲の拒否も含み、すべてが C++ の UB を意味するわけではない。
- `exhausted`：観測の実行枠が不足した。C++ が停止しないことも、入力が安全であることも意味しない。

枠は再帰的な文の実行を進めるための深さ上限であり、C++ の時間や IR の仕事量ではない。各再帰に小さい枠を渡すため、有限の枠による評価器自体は停止する。しかし、それだけでは C++ のループの停止証明にはならない。

`LoopProgram.Terminates` は、ある実行枠と結果で `callFuel = finished result` となることとして定義する。公開する部品の前提条件下でこの存在を証明しなければならない。`runFuel_success_mono` と `callFuel_success_mono` は、一度正常終了した実行について枠を増やしても同じ結果・状態・費用・領域となることを証明する。`runFuel_success_unique` と `callFuel_success_unique` は、異なる枠で正常終了した二つの実行の結果全体が一致することを証明する。これら4定理の `#print axioms` は Lean の標準公理 `propext`、`Classical.choice`、`Quot.sound` のみを報告する。停止や一意性を新しい公理として仮定していない。

実際の部品の停止証明には、変化する添字や数値の単調性、不変条件、減少する測度を使って十分な枠の存在を証明することが引き続き必要である。まだ持ち込みのループを持つ部品について、その全入力の停止定理を完成したとはしない。

## 対応範囲と費用

通常の条件式を持つ `while` と、初期化・条件・更新の省略を含む基本的な `for` に対応する。対応ループの内部の `break` も扱う。条件内の通常関数の直接呼び出しも、下記の規則で扱う。条件内での変数宣言、`continue`、`switch`、`do/while`、範囲 for、評価値を使うインクリメント、配列、一般の STL 等は未対応で拒否する。整数のインクリメント文は型付きの読み出し・加減算・格納に落とし、符号付きの範囲超過と符号なしの剰余は式の共通規則に従う。bool のインクリメントは扱わない。文としての複合代入5演算は状態変換器と共通の規則を使う。

`break` は `Stmt.breakLoop` へ変換し、仕事量を1加え、中断を示す `Step.breaking` を返す。return の値とは独立した状態である。順次実行は中断後の文を実行せず、スコープは中断した場合も局所セルと束縛を破棄する。最も内側の while が中断を処理し、フラグを消してそのループを終了する。for は本体と更新式を while の本体内で順次実行する形なので、中断した場合は更新式も実行しない。内側のループの break は外側のループを終了させない。変換器は対応ループの外側の break を拒否し、評価器も未処理の中断が関数から漏れるモデルを `fault` とする。ループのない `Stmt.run` は break を成功扱いしない。

`break_succeeds` は中断の状態と費用、`break_sequence_skips` は中断後の文を実行しないこと、`while_break_exits` は非零の条件を評価した直後の break により中断を処理してループを抜けることを証明する。既存の実行枠についての正常終了の不変性・一意性の定理は、この文を含む全 `Stmt` を対象に拡張する。これらも持ち込みのアルゴリズム全体の停止証明の代替にはしない。

追加した3定理と既存の枠の不変性・一意性4定理の `#print axioms` は、標準公理 `propext`、`Classical.choice`、`Quot.sound` の範囲内のみを報告する。

条件式の費用に判定を1追加し、最後の偽となる判定も数える。選ばれた本体、更新式、初期化、代入、return の費用を状態に蓄積する。追加領域は、局所セルの破棄を含む既存の `State.observe` の抽象上界を使う。枠の値そのものを時間・領域の上界として使わない。

## 検査

```sh
python3 tests/test_loop_ir.py
python3 tools/check_public.py
```

専用スクリプトが C++ と Lean のケースを生成し、通信禁止下で、while の参照更新、for の累積、二重ループ、スコープの破棄、途中の return と更新式の省略を比較する。break では、入れ子の最内ループだけの中断、局所変数の破棄、for の更新式の省略、直後のオーバーフローする文を実行しないこと、その後の return、費用・領域を比較する。C++ は UBSan で確認する。枠不足、無限ループの有限観測、符号付きオーバーフロー、不正な参照を分けて確認する。条件の `<` を `<=` に変える変更、更新の `++` を `--` に変える変更、加算内容を変える変更、break を除く変更で正常な結果の検査が失敗することも確認する。これは有限ケースでの変換検査であり、部品の全入力証明の代替にはしない。continue・switch 等の未対応構文を拒否することも確認する。

除算・剰余の式もスカラーの共通規則を使う。有限ケースで Euclid の反復と負数の逐次半減を生成 C++/Lean で比較する。これは持ち込み部品の全入力証明ではない。

共有基盤として Lean import・ビルド・`leanchecker`・CI の公理監査に登録する。`floor_sum_unsigned` は生成したループを関数全体へ接続し、対象範囲の全入力について停止・状態評価の安全性・結果・時間と追加領域を証明して公開登録した。[仕様と検証](floor_sum_experiment.md)を参照する。配列と一般の STL、ビット演算、continue、他の持ち込み部品の全入力証明、既存2部品の移行、全件の公開登録は引き続き未完了である。

値引数の内部呼び出し `Stmt.invoke` も実行枠付き評価器に接続した。本体の fault・exhausted を伝播し、正常終了後に呼び出し側へ返却値を戻す。正常終了した実行枠の単調性と、呼び出し規則の接続定理を検査する。値引数とスカラー返却値を持つ直接呼び出しの AST 変換も追加した。ループ本体での呼び出しと、ループを持つ呼び出し先を扱う。再帰は拒否する。詳細は [状態変換器](state_converter.md#値引数の関数呼び出しモデル) を参照する。

## 呼び出しを含むループ条件

条件に呼び出しがある場合、`loop_with_calls` は `while(true)` の反復内に「呼び出し、一時値の条件判定、真なら元の本体、偽なら break」を置く。呼び出しは反復の開始と最後の偽の判定でも実行し、参照先の更新を保持する。for では真の分岐に本体と更新式を順に置き、本体が break / return したら更新式を省略する。入れ子の break は最内のループで処理する。

各反復を追加の scope で包み、呼び出しの返却値などの私有セルと binding を破棄する。条件の一時値は本体・更新式の終わりまで保持するため、領域は C++ の一時値の実際の寿命より保守的に数える。隠れた返却値セルを C++ の lvalue として参照する経路はない。生成した真の while 条件・分岐・偽の break の費用も数える。呼び出しのない条件は従来の IR をそのまま生成し、既存の費用・公開モデルを保持する。

参照呼び出しは条件の式全体に限る。参照呼び出しを短絡式や他の引数の中へ入れること、条件変数の宣言は引き続き拒否する。値引数だけの純粋な呼び出しは既存の式変換の範囲を使う。

CppReferenceCommands の `conditionIteration` は生成する反復の構造と一致する。3補題は条件が偽のとき更新済みの範囲を保持して break すること、真のとき評価後の状態で本体を実行して scope を閉じること、条件呼び出しの fault を伝播することを証明する。真の分岐の本体が返す return / break を保持する。正常終了後の fuel 増加と結果の一意性は既存の全 Command の補題を使う。

`tests/test_call_loop_conditions.py` は参照条件の while / for、最後の偽の更新、for 更新の省略、即時 return、入れ子、値引数の条件を160ケースで生成 Lean / 独立した期待値 / UBSan 付き C++ と照合する。生成した各参照条件の反復を conditionIteration と rfl で照合し、3補題が扱う構造との一致を確認する。1反復と199反復で peak が等しいことも検査する。caller の他セル・メモリ長の保持、領域・仕事量の上界、fuel 不足、範囲超過、不正参照、成功時の fuel 増加、改名の不変性、境界と更新の改変による結果不一致、未対応条件の拒否を確認する。有限ケースの成功を各部品の全入力の停止・費用証明とはしない。

```sh
python3 tests/test_call_loop_conditions.py
```
