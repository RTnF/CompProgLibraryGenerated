# 分岐・更新・参照の共通変換器

現在の公開対象は safe_mod と2種類の floor_sum。signed の全入力証明と公開経路は末尾の「signed 本体全体」と「依存ヘッダと公開 signed 変換契約」に記録する。以下の段階ごとの記録で述べた残作業は、その後の段階で解消したものもある。

`verifier/state_ir.py` は、スカラー変換器と同じ固定 Clang フロントエンド・ABI 確認・型・式変換を使い、文と参照を型付き IR に落とす。`Proofs/CppState.lean` が共通の状態・文評価器を定義する。変換規則は文・型・操作に対応し、部品名・ソースハッシュでモデルを選ばない。

## 対応する文と状態

スカラーの自動変数の初期化、直接の変数への代入、通常の `if` / `else`、return、空文、ブロック、文の順次実行を扱う。分岐の選ばれた側だけを実行し、return 後の文を実行しない。ブロックと分岐のスコープを抜ける際に追加した局所束縛と局所セルを破棄する。外側と同名の局所変数も宣言 ID によって区別する。

値を捨てる文としての `+= -= *= /= %=` を、直接の書き込み可能な変数・参照について扱う。Clang の `computeLHSType` と `computeResultType` を使い、左辺を演算型へ変換して右辺と演算し、結果を格納型へ変換する。単に格納型で演算する規則にはしない。右辺の副作用と間接的な左辺は拒否するため、左辺の場所の評価は直接の束縛の指定だけである。複合代入の値を別の式で使う場合とビット演算の複合代入は未対応で拒否する。

関数の入力は整数・bool の値、またはそれらへの lvalue 参照。参照は呼び出し側のメモリセルのアドレスに対応する。同じセルへの複数の参照を許し、書き込み後の別名からの読み出しも新しい値を見る。const 参照・const 値の束縛からの書き込みは拒否する。値引数は独立した私有セルを持ち、更新は呼び出し側の値を変えない。セルの型と参照の型を照合し、範囲外アドレス・型不一致・不正な整数値・引数の個数や種別の不一致を拒否する。

参照引数のアドレスは呼び出し時に存在する呼び出し側のセルに限る。後から確保する値引数の私有セルを、参照引数として指定することはできない。呼び出し側は、mutable 参照に渡すオブジェクトが実際に変更可能であることを前提とする。所有権、ポインタ、参照の寿命を伴う一般のヒープモデルは未対応。

局所参照、rvalue 参照、参照の返却、関数ポインタ・再帰を伴う内部呼び出し、配列、クラス、条件演算子、短絡演算、`if` の初期化・宣言・constexpr 条件などは拒否する。標準ライブラリは [スカラーの std::swap 契約](scalar_stl_contracts.md) の範囲を追加した。ループとインクリメント文は [停止条件を持つループ基盤](loop_converter.md) で追加した。式の対応範囲と整数の意味は [スカラー基盤](scalar_converter.md) に従う。返却型も確認し、参照を値として誤ってモデル化することを拒否する。

## テンプレートの具体化

型引数だけを持つ関数テンプレートについて、Clang が生成した具体化本体を扱う。非型引数、既定引数、明示的特殊化などは未対応。具体化がないテンプレートは拒否する。IR には `coverage = concrete_instances_only` と具体化一覧を記録する。依存型の主テンプレート全体についての検証が済んだとはしない。

`experiments/verification/template/update_extrema.hpp` は、両系列の持ち込みテンプレートの `chmin`・`chmax` 本体を保持して `cp::` に置いた候補である。専用の具体化ソースは `tests/imports/update_extrema_instantiations.cpp`。`int,int` と `unsigned int,unsigned int` の4具体化を共通変換器で生成する。

用途は比較条件が成り立つときだけ左辺を右辺で更新し、更新したかを bool で返すこと。同一の整数型では `chmax` は大きい方、`chmin` は小さい方を残し、同値なら更新しない。2引数が同じ変数を参照する場合も更新しない。符号や幅が違う型、ユーザー定義型など、未確認の組み合わせについてこの仕様を主張しない。一般の型には比較と代入の条件、比較時の変換、代入時の表現可能範囲などの定義が引き続き必要である。

元のテンプレート `.cpp` も直接 include して具体化し、元の Clang AST から生成する IR と候補の IR が一致することを二系列それぞれで検査する。この対象宣言を選ぶ AST filter は宣言の抽出にだけ使い、意味変換の規則の選択には使わない。他の補助関数やテンプレート全体を検証したとはしない。

## 費用・領域と証明

式の抽象仕事量に、局所変数の格納、代入、条件判定、return を各1追加する。`int` と `unsigned int` の現在の生成モデルでは、更新する経路は9、更新しない経路は7の仕事量になる。参照束縛と呼び出し側の引数評価はこの関数本体の仕事量に含めていない。C++ 側の追加費用との対応は信頼境界として別途定める。

追加領域を、呼び出し側のセルを除いた私有セル・束縛と、式のノード数による一時値の保守的な上界で表す。最大同時領域を `peak` に残す。現在の `chmin`・`chmax` の具体化では5となる。これは Lean の環境リストや実コンパイラのスタック使用量の実測値ではない。スカラーの幅と C++ 側の参照・一時値の領域契約が必要である。

評価器は文の木に対する構造的な再帰で終了する。成功した代入がメモリのセル数と束縛を変えないことを `assign_preserves_storage` で証明する。エイリアスのアドレスを維持するための基礎となる不変条件である。一般の状態プログラムの結果・未定義動作の不在・全体の費用と領域の定理、C++ からの意味対応の完全な監査はまだない。

`chmin`・`chmax` の4具体化には [全入力の生成モデルの証明](extrema_proofs.md) を追加した。正規化した参照先の配置について、結果・更新後のメモリ・成功・費用と領域・エイリアス・後続セルの保持を扱う。これは一般の状態プログラムや主テンプレート全体の証明とは区別する。

## 検査と残作業

```sh
python3 tests/test_state_ir.py
python3 tools/check_public.py
```

検査は通信禁止下で、両系列の実際のヘルパーからの IR 一致、具体化した候補の C++ 実行と生成 Lean の返り値・更新後のセル・仕事量・追加領域を確認する。符号付き整数の最小・最大値、符号なしの最大値、同値とエイリアス、局所変数の破棄、shadowing、早期 return、型不一致と不正アドレスを扱う。境界条件の故意の変更による検査失敗も確認する。C++ 実行は UBSan で確認する。

複合代入5演算の小規模比較、左辺・右辺のエイリアス、64 bit の中間演算から32 bit への格納、bool の整数昇格、範囲外の符号付き変換の拒否を確認する。持ち込みの [safe_mod](safe_mod_experiment.md) は元ヘッダの対象宣言から直接生成し、候補の IR と一致することを検査する。ヘッダを読む際の include 検索先を `--include-dir`、対象宣言の抽出を `--declaration-filter` で指定できる。対象外の宣言まで検証したことにはしない。

共有基盤は `verifier/support.toml` と `Proofs.lean` に登録する。候補は公開せず `experiments/` に保持する。一般の型条件の定式化と証明、任意のアドレス配置・寿命への意味対応、元宣言台帳の全件の対応、公開登録、配列・ループ・STL、既存2部品の移行などは引き続き未完了である。

## 標準 assert の実行チェック

`scalar_assert.py` は固定ツールチェーンの cassert から採取した __assert_fail の宣言と、assert マクロの展開形を照合する。条件は純粋なスカラー式に限り、独自マクロ、同名関数の影・定義、assert を無効にした展開は受理しない。`Stmt.check` は評価値が0なら失敗し、非0ならメモリ・束縛を保って仕事量と領域を観測する。条件を証明の仮定として追加せず、`check_succeeds` と `check_fails` で実行規則を証明する。ループの実行枠の単調性にもこの文を接続する。失敗は検証失敗を表し、C++ の SIGABRT やプロセス資源の挙動はモデル化しない。正常終了を証明するにはチェックが通ることも示す必要がある。

assert の条件に含まれる && と || は短絡評価する分岐へ変換する。右辺を評価しない経路を保持し、論理結合子ごとに成功する追加チェックで仕事量を保守的に計上する。一般の式や if 条件の論理演算にはまだ対応していない。リテラル同士の左シフトは幅内の非負のシフト量と対応整数範囲を検査し、同じ抽象仕事量の乗算へ変換する。変数のシフト、signed の範囲外・実装依存のシフトは拒否する。

`tests/test_scalar_assert_ir.py` は真・偽、短絡によるゼロ除算の回避、ループ内のチェック、2^32境界、条件を変えたモデルでの検証失敗、利用者マクロ・同名失敗関数・NDEBUG の拒否を検査する。元 signed floor_sum の2個の assert は認識する。floor_sum だけを選ぶ AST には safe_mod の定義が含まれないため、その呼び出しは拒否する。signed 関数全体の変換・証明は未完了である。

## 値引数の関数呼び出しモデル

Lean の `Stmt.invoke` は、純粋な引数式を呼び出し側で評価し、新しい束縛に値をコピーして本体を実行する。呼び出し先の束縛から呼び出し側の変数を参照することはできない。正常終了時は呼び出し側のメモリと束縛を復元し、型範囲内の返却値を読み取り専用の一時セルへ格納する。返却値なし、型範囲外の値、関数外へ漏れる break、引数不一致は失敗する。参照引数、グローバルへの書き込み、再帰呼び出しの C++ 対応は含めない。

引数評価の仕事量とコピー、呼び出しの開始・終了を計上する。領域は保持した引数値、保存した呼び出し側束縛、呼び出し先の私有セル・束縛、返却値の一時セルを含む保守的な上界である。`CppInvokeProofs` は返却処理の状態保持と費用、失敗条件、本体の実行から呼び出しへの接続を証明する。ループを含む本体では失敗と実行枠の不足を区別し、正常終了した実行枠の単調性を維持する。

`tests/test_invoke_model.py` は共通変換器で生成した C++ ヘルパー本体を手書きの呼び出し IR へ接続し、値コピー、呼び出し側の参照の別名、返却値、ループと失敗条件を検査する。C++ の実行との比較、ヘルパーの改変による結果不一致も確認する。通常の C++ の直接呼び出しから invoke を生成する処理も追加した。signed floor_sum 全体を変換・証明できたとは扱わない。


呼び出し先は同じ AST dump の FunctionDecl の宣言 ID と previousDecl の連鎖で解決する。前方宣言・定義後の再宣言は定義と照合し、本体の IR を呼び出しへ埋め込む。名前だけで外部関数の意味を仮定せず、選択した AST に定義がない呼び出しを拒否する。再帰を検出し、callee の値引数・結果型と Clang が生成した引数の型変換を照合する。グローバル参照・書き込みは従来の非局所宣言拒否規則で止まる。Clang が具体化した型テンプレートの通常関数と、その内部の呼び出しも [具体化した呼び出しの経路](template_converter.md#具体化したテンプレートの内部呼び出し) で扱う。名前の衝突しない通常関数とテンプレート関数のオーバーロードも宣言 ID で区別する。出力名が衝突するオーバーロード、参照・ポインタ・void の返却、既定引数は現在未対応である。

呼び出しは初期化、返却、代入・複合代入の右辺、if 条件、値を捨てる文に対応する。ループ本体と for の初期化・更新にも同じ規則を使う。while/for の条件は、反復ごとに呼び出しを実行する [ループ条件の変換](loop_converter.md#呼び出しを含むループ条件) を使う。引数内の入れ子の呼び出しと算術式中の複数の呼び出しは、純粋な値引数の呼び出しに限って順に展開する。呼び出しで外側の値は変わらないため、対応範囲では評価順によって返り値は変わらない。副作用のある引数、短絡式・条件演算子、assert 条件内の呼び出しは拒否する。

代入・返却・if・値を捨てる文の呼び出し一時値は、追加したスコープを抜ける時に破棄する。初期化に用いた一時値は宣言した変数と同じ囲みスコープまで保持する。この保持は C++ の一時値より長いため、領域の保守的な上界として扱い、C++ の正確な一時値の寿命を再現したとはしない。ループ本体のスコープで一時値を破棄し、反復間に蓄積させない。

`tests/test_scalar_call_ir.py` は生成した呼び出しモデルと UBSan 付き C++ を比較する。前方宣言と定義後の再宣言、const の引数と局所変数、複数の宣言、入れ子の呼び出し、符号なしのラップ、呼び出し側の参照の別名と別セル、ループ内とループを持つ callee、反復間で領域が増えないことを検査する。関数・引数の改名でも IR が同じになり、本体の変更では IR と結果が変わること、未検証の外部呼び出し等が拒否されることも確認する。これは有限ケースの変換検査であり、各部品の全入力証明は別途必要である。


## 同じ AST からの入力ファイル選択

`--direct-file` は名前フィルタに代わり、翻訳単位の JSON を一度だけ取得して入力ファイルの通常の関数・関数テンプレートを取り出す。関数の宣言 ID と再宣言の連鎖は同じコンパイラ実行の値を保持する。名前空間内の関数も扱い、別ヘッダの宣言とマクロの複数位置を持つ宣言は除外する。別ヘッダの未検証関数に依存した場合は、その定義がないため呼び出しを拒否する。型やグローバル変数、クラスの検証をこの選択処理だけで完了したとはしない。

Clang の出力は一時ファイルへ書き、`ast_stream.py` が翻訳単位の直下の宣言を順に読む。標準ヘッダの巨大な宣言木は JSON テキストとして扱い、全体を Python の AST 辞書へ展開しない。固定 Clang の loc にある includedFrom と入力ファイルの位置を照合し、主ファイルの繰り返し位置で省略されたファイル名を補う。この位置表現と出力形式はフロントエンドの信頼境界である。空の入力と末尾の破損、文字列のエスケープと小さい読み取り境界を検査する。

元 floor_sum ヘッダでは、この経路から safe_mod・floor_sum_unsigned・floor_sum を取得し、[実験用の全体モデル](../experiments/verification/number/floor_sum_signed_model.lean)を生成する。最初の2関数は従来の個別生成と一致する。signed のモデルは、負の数学的結果や signed 範囲外への変換でまだ fault になる。全入力の意味対応を完了したとは扱わない。`tests/test_direct_file_ast.py` は生成全文の一致、入力ファイルと include の区別、callee ID の一致、通常の小規模結果と UBSan 付き元 C++ の比較、既存の範囲外変換の失敗を検査する。


`--signed-conversion gcc13.3-lp64-twos-complement` を明示すると、[対象コンパイラの変換契約](scalar_converter.md#対象コンパイラの-signed-整数変換)で範囲外の signed 変換も生成できる。通常の代入・初期化・引数・返却の Clang の変換と、複合代入の格納型への変換に適用する。既定の checked モデルはそのまま保持する。元 signed floor_sum の[対象変換を使うモデル](../experiments/verification/number/floor_sum_signed_gcc_model.lean)は別に生成・全文照合する。負の結果と signed 範囲外の数学的な和も復号して返し、小規模・型境界・最大 n の閉形式で元 C++ と比較する。関数全体の全入力証明と公開は未完了である。

`CppInvokePreparation` は任意の成功した引数束縛について、コピーしたセルとそのアドレス・書き込み可否、既存のメモリ・束縛の保持、セル数・束縛数・仕事量と最大領域の形を証明する。個数と型が一致すれば束縛が成功することも示す。prepare_shape は引数式の仕事量をノード数へ接続し、呼び出し準備の仕事量を「元の仕事量＋開始1＋引数式のノード数の合計＋引数コピー数」として示す。最大領域は、引数評価時の領域と、保存した呼び出し側束縛・引数の私有セル・callee の束縛を持つ準備後の領域の最大値である。

invoke_composed は準備、本体の正常終了、返却値の型範囲を前提として、invoke が呼び出し側のメモリと束縛へ返却値の一時セルを追加して正常終了することを証明する。仕事量は引数評価・コピーと本体の増分に開始・終了の2を足したものとなり、領域には返却時の観測も含める。`tests/test_invoke_model.py` では、実際の C++ copy ヘルパーの型と本体から生成したモデルにこれらの定理を適用し、同じ caller 変数を2回渡しても独立したコピーになること、返却値・caller の保持・仕事量・領域を確認する。callee 本体の全入力証明と、異なる baseMemory・初期 peak で既存の本体証明を再利用する一般の対応は別途必要である。


`CppWorkFrame` は任意の状態へ既存の仕事量を加える `addWork` について、引数評価・束縛・呼び出し準備・返却・文の実行・燃料付き実行が可換となることを証明する。正常終了では最終仕事量に同じ量を加え、メモリ・束縛・baseMemory・peak・返却値・break は保持する。失敗と燃料切れも保持する。対象は全 Stmt 構成子であり、ループ・入れ子の内部呼び出しを含む。`FloorSumWorkFrame.body_runs_withWork` は生成された unsigned floor_sum 本体の全入力証明に適用し、仕事量の増分の上界4229と対数上界、領域上界25を保持する。呼び出し側で保存する領域に合わせた baseMemory と初期 peak の移し替えは引き続き必要である。

`ExtremaReferences` は型付き2参照について任意の caller メモリとアドレス配置を扱う。実際の引数束縛・型検査・代入・条件分岐・返却・scope を接続し、4生成済みの extrema 具体化を rfl で照合する。p=q も許し、参照先の2セルだけに型と値の前提を置く。更新範囲は destination 1セル、他のセルとメモリ長、右辺の値を保持し、仕事量7/9・領域5で正常終了する。主テンプレート全体、ユーザー定義型、一般の C++ オブジェクトの寿命・所有権の検証は未完了である。

## 参照引数の内部呼び出し基盤

値引数の invoke と別に、CppReferenceInvoke に混在した値・lvalue 参照引数のモデル基盤を追加した。参照は元の caller の binding とメモリで権限・型・範囲を検査し、caller の更新済み範囲を保持して私有セルを破棄する。CppReferenceCommands と state_ir.py で呼び出し元の参照 CallExpr を自動生成し、文・分岐・スコープ・ループ本体へ合成する。参照呼び出しは式全体に限り、複合式・引数内の参照呼び出しや一時参照は拒否する。[意味・証明・検査と残作業](reference_invoke.md)を参照する。
