# ratio

`cp::Ratio` は符号と大きさで持つ有理数 `(-1)^s * n / d` である。`experiments/library/cpp/number/ratio.hpp` の `Ratio`（`normalize`）から作った。フィールドは `s`（負なら 1、それ以外は 0）、`n`（分子の大きさ）、`d`（分母の大きさ）の 3 つで、すべて `unsigned long long`。

元のソースからの変更（検証できる形にするために書き換えた）:

- 符号付き `T n, d` ではなく、符号を別の符号なしフィールド `s` に分けた（検証器の符号なし 64 bit のセルだけで扱えるようにするため。`LLONG_MIN` の符号反転のオーバーフローも起きない）。
- `normalize` は自分を書き換えるメンバー関数ではなく、新しい値を返すフレンド関数 `normalize(r)` にした。`gcd` は `std::gcd` を呼ばず、ユークリッドの互除法のループを関数の中に書いた（検証済みの関数は別の関数から呼べないため。証明は `Proofs/ShiftN.lean` で `gcd_u64` のループの補題を再利用している）。
- 演算子（`+`, `-`, `*`, `/`, `<=>` など）、入出力は含めていない。含めていない演算は、実験用のソースに残っている。

結果（`Proofs/RatioCall.lean`、一般の入力について証明）: 前提は `d ≠ 0`（`assert` で確認する。破ると未定義の実行ではなく異常終了）。`g = gcd(n, d)` として、`normalize(r)` の各フィールドは、`n = 0` なら `(s', n', d') = (0, 0, 1)`、そうでなければ `(s, n / g, d / g)`。フィールドごとの関数 `Ratio_normalize_s`・`Ratio_normalize_n`・`Ratio_normalize_d`（2 つ以上のスカラーフィールドを持つクラスは変換器がフィールドごとの関数に分ける）について、`Ratio_normalize_*_correct` が上の値を返すことを証明している。
- 時間はループの反復回数が `2 * (d のビット数) + 2` 以下（仕事量は `80 * log2 d + 200` 以下）、追加領域は定数個の局所変数。

定理に含めていないこと: コンストラクタ `Ratio(s, n, d)`（2 フィールド以上のクラスのコンストラクタは変換器が関数にしない。C++ のテストで確認している）、`n`・`d` が互いに素になること（`gcd(n / g, d / g) = 1`）の Lean での定理（C++ のテストで確認している）。C++ のテストは `tests/ratio.cpp`（端の値と乱数で `std::gcd` と比較する）。
