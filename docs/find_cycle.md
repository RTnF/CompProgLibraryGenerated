# find_cycle

`cp::ListGraph<Cost, E>::find_cycle_directed()`（`library/graph/graph_list.hpp`）は、有向グラフの単純閉路を1つ見つける。閉路を順に巡る辺 `E` の配列を返し、閉路がなければ空の配列を返す。自己ループは1辺の閉路になる。隣接行を添字の小さい頂点から調べ、各行の挿入順に探索する。

## 前提と計算量

- 辺の始点 `from` はその辺を格納した隣接行の番号で、行き先 `to` は `[0, n)`。自己ループ、平行辺、空グラフを扱う。`operator[]` で行を編集した場合もこの前提を満たせばよい。入力と途中の値は C++ の型の範囲内とする。
- 辺型には `from`・`to` と `E(-1, -1)` の構築が必要。原本と同じく、空グラフでも番兵を一度構築する。既定の `Edge<Cost>` の共有 ID はそのとき1つ進む。
- 時間は O(1 + n + m)、追加領域は親辺・訪問色・閉路の配列と再帰フレームを含め O(n)。`m` は実際の隣接行に含まれる弧の総数。汎用辺でコピー等に固有の費用がある場合はその費用がかかる。

## 元のソースからの変更

原本の再帰ラムダを `ListGraph` の非公開メンバー `find_cycle_dfs` に移した。辺の元の参照型、始点と隣接行を選ぶ順序、番兵の構築、辺配列を返す API を保つ。

## `ListGraph` メンバーの検証

`find_cycle_directed_spec` は任意の `Cost` と値として扱う `E` で、構築子の契約をもとに結果・停止・グラフの保持を示す。閉路は元の辺値を閉路の順に並べたもので、始点の重複がなく、長さは `n` 以下。空の結果は閉路が存在しないことを意味する。構築直後の時計 `tc` から `tc + 9n + 2m + 5` 以下で終わる。`find_cycle_directed_default_spec` は既定の `Edge<T>` の共有 ID と開始時の時計 `t0` からの上界 `t0 + 10n + 2m + 7` も示す。

隣接リストの CSR 射影は、行の順序・各弧の位置・自己ループを保持する。`FInv` の色、カーソル、スタックは生成した再帰探索と対応し、各スタック上の親辺は元の `E` を保持する。灰の祖先に向かう辺で親をたどると単純閉路が得られ、全頂点を調べても閉路が見つからなければ完了時刻がすべての弧に沿って減少する。`find_cycle_workspace_slots` が作業配列・結果配列と再帰フレームの個数を合わせて `4n` 以下に抑える。

サニタイザ付き C++ 回帰は閉路の有無を到達可能性の閉包と比較し、各辺の ID・費用・順序を検査する。独自辺型の非 const コピー・代入と空グラフの ID 更新も検査する。C++ と生成 Lean の差分では、探索を繰り返した後の辺 ID も照合する。

## CSR の自由関数

`cp::find_cycle(head, target, state, it, stk, cyc, n)`（`library/graph/find_cycle.hpp`）は、有向グラフの閉路を1つ見つける反復 DFS である。

- グラフは CSR 形式の配列で渡す。頂点 `v` から出る辺の行き先は `target[head[v] .. head[v + 1])`。
- 再帰ラムダを、明示的なスタック `stk`（長さ `n`）を使った反復に置き換えた。
- 結果は辺の配列ではなく、閉路を作る頂点の列とする。列は呼び出し側の `cyc[0 .. k)` に書き、頂点数 `k` を返す。
  - `cyc[i] -> cyc[i + 1]`（`i < k - 1`）と `cyc[k - 1] -> cyc[0]` が辺である。
  - 閉路がなければ `0` を返す。自己ループ `v -> v` は `k = 1` の閉路である。

### 使い方と前提

使い方: `state` の全要素を `0` にして渡す。`it`、`stk`、`cyc` は長さ `n` の作業配列で、中身は何でもよい。

前提（`Pre`）:

- `head.size() == n + 1`、`head` の要素は非負、`head` は広義単調増加。
- 辺はすべて `[0, n)` の頂点を結ぶ（すべての `target[p]` が範囲内で非負）。
- `state`/`it`/`stk`/`cyc` の長さは `n`。
- `head[n] + 3n < 2^62`（`int` に収まる入力はこれを満たす）。

### 結果（`Proofs/Cpp/FindCycle.lean` の `find_cycle_spec`）

返り値 `k` と書かれた `cyc` について `Out` が成り立つ。

- `k == 0` なら、グラフに有向閉路はない。どの辺 `u -> w` についても、`w` から `u` へ辿れない。
- `k > 0` なら、`k <= n` で、`cyc[0 .. k)` は範囲内の互いに異なる頂点であり、`cyc[i] -> cyc[(i + 1) % k]` が辺である（`CycOut`）。
- 手数は `5n + head[n] + 3` 以下、つまり `O(n + m)`。追加領域は局所変数だけである。

### 証明

- **探索の数学**（`Proofs/Math/FindCycleInv.lean`/`FindCycleStep.lean`/`FindCycleSpec.lean`/`FindCyclePhi.lean`）
  - 状態 `FS` は、色（白・灰・黒）、反復子、終了時刻（ghost）、スタックからなる。
  - 不変条件 `FInv`: スタックは灰の頂点の道であり、黒の頂点の辺は終了時刻が小さい黒の頂点へ向かう。
  - 4 つの遷移（根、push、黒の頂点の skip、pop）が `FInv` を保つ。
  - 最終状態から仕様を導く: 全部黒なら閉路なし（`acyclic_of_done`）、灰の頂点への辺があれば閉路（`Found`、`cycout_of_found`）。
  - ポテンシャル `phiF`（未走査の辺・白い頂点・スタックの高さ）が、ループの回数を抑える。
- **生成モデルとの対応**（`Proofs/Cpp/FindCycle.lean`）
  - C++ の配列を `FS` の欄として読み（`Abs`）、各ループに不変条件 `OI`/`II` を与える。
  - 後処理は 2 つのループである: 閉路の始点をスタック上で探すループと、`cyc` へのコピー。

### 検証

- `verifier/lean_translate.py` が関数全体を翻訳する。
- 差分テスト `tests/diff/find_cycle.py` は、頂点数 0〜10 のランダムな有向グラフで、モデルと C++ の結果を比べる。
- C++ のテスト `tests/find_cycle.cpp` は、頂点数 0〜8 のランダムな有向グラフで、到達可能性の閉包による基準と比較する（ASan/UBSan 付き）。

返す閉路の選択は仕様に含まない。
